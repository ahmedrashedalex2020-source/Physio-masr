# ربط قاعدة بيانات سحابية موحدة (Firebase Firestore) ومزامنة لحظية صامتة

تحويل نظام التخزين في تطبيق إدارة جلسات العيادة إلى قاعدة بيانات سحابية حقيقية ودائمة عبر **Firebase Firestore**، للقضاء نهائياً على مشكلة فقدان التعديلات واختلاف البيانات بين الكمبيوتر والموبايل، مع استبدال التحديث الدوري المتكرر بمزامنة لحظية صامتة تعمل عند حدوث تغيير فعلي فقط.

---

## المراجعة والقرارات المعتمدة

> [!IMPORTANT]
> تم بناء هذه الخطة بناءً على اختياراتك المؤكدة لحل جذور المشكلة التقنية الحالية (حيث أن الملفات المؤقتة على السيرفر لا تدوم وتختلف بين بيئة المعاينة وبيئة الموبايل المنشورة):

- **قرار معتمد 1 (قاعدة البيانات المركزية)**: الاعتماد الكامل على قاعدة بيانات سحابية حقيقية (**Firebase Firestore**) لتكون المصدر الوحيد الموثوق للبيانات (Single Source of Truth) لجميع الأجهزة.
- **قرار معتمد 2 (آلية المزامنة ومنع التحديث المستمر)**: إلغاء المؤقت الزمني المزعج (الذي كان يعيد طلب البيانات كل 8 ثوانٍ وعند كل لمسة للشاشة) واستبداله بمستمع لحظي صامت (`onSnapshot`) يقوم بتحديث السجل الذي تغيّر فقط في الخلفية دون أي وميض أو إعادة تحميل للصفحة.
- **قرار معتمد 3 (حفظ فوري ومضمون للتعديلات)**: كتابة كل عملية (إضافة جلسة، تعديل جلسة، تبديل حالة الدفع، أو حذف جلسة) مباشرة في قاعدة بيانات Firestore مع التحقق الصارم من عدم تكرار نفس الجلسة، وبذر البيانات الأساسية للعيادة (68 جلسة) تلقائياً عند التهيئة الأولى فقط.

---

## 1. نظرة عامة والمفهوم الأساسي

- **ماذا يقدم هذا التحديث**: يربط نسخة الكمبيوتر ونسخة الموبايل (سواء عبر المتصفح أو تطبيق الـ PWA المثبت) بقاعدة بيانات سحابية واحدة مشتركة في الوقت الفعلي.
- **المشكلة التي يحلها**:
  1. **تطابق 100% بين الكمبيوتر والموبايل**: في السابق كان الكمبيوتر يقرأ من خادم التطوير بينما يقرأ الموبايل من رابط النشر أو من ذاكرة مؤقتة تُمحى عند خمول السيرفر؛ الآن يتصل الجهازان بنفس قاعدة بيانات Firestore السحابية مباشرة.
  2. **إيقاف التحديث المستمر بدون داعي**: إزالة طلبات الشبكة المتكررة كل 8 ثوانٍ ومؤشرات التحميل المتقلبة التي كانت تربك المستخدم أثناء العمل.
  3. **ثبات التعديلات والإضافات**: كل تعديل أو إضافة يُحفظ فوراً في السحابة ولا يُفقد أبداً عند إعادة فتح التطبيق أو تحديث الصفحة.

---

## 2. تجربة المستخدم والتصميم المرئي

- **رحلة المستخدم مع المزامنة اللحظية**:
  1. عند فتح التطبيق على الكمبيوتر أو الموبايل، يتم الاتصال بقاعدة بيانات Firestore السحابية وجلب أحدث السجلات فوراً.
  2. إذا كانت قاعدة البيانات السحابية فارغة في أول تشغيل، يقوم النظام تلقائياً برفع البيانات الأساسية للعيادة لمرة واحدة فقط.
  3. عند إضافة جلسة جديدة أو تعديل حالة الدفع على الموبايل، تظهر التغييرات في نفس اللحظة على شاشة الكمبيوتر (والعكس) بهدوء تام ودون إعادة تحميل الجدول أو فقدان موضع التمرير.
- **الهوية البصرية ومؤشر الحالة**:
  - الحفاظ على التصميم الطبي الاحترافي المريح للعين باللغة العربية (`RTL`).
  - استبدال شريط التحديث المتقلب بمؤشر حالة ثابت وهادئ يعكس الاتصال الفعلي بالسحابة (**"متصل بقاعدة البيانات السحابية"** باللون الأخضر الزمردي) ولا يتحول إلى حالة عدم الاتصال إلا عند انقطاع الإنترنت الفعلي عن الجهاز.
  - رسائل تنبيه واضحة (Toast) تؤكد نجاح حفظ الإضافة أو التعديل في قاعدة البيانات السحابية.

---

## 3. القرارات التقنية والمفاضلات

- **القرار الأول: الانتقال من ملفات السيرفر المحلية إلى Firebase Firestore**
  - *النهج المختار*: تخزين مجموعتي الجلسات (`sessions`) وملفات العملاء (`clients`) في Firestore.
  - *لماذا*: الخوادم السحابية المؤقتة (Serverless / Containers) تعيد ضبط ملفاتها المحلية وتفصل بين بيئة التطوير وبيئة المشاركة، مما يسبب اختلاف البيانات وعدم حفظ التعديلات. أما Firestore فيضمن بقاء البيانات للأبد وتطابقها عبر أي رابط أو جهاز.
- **القرار الثاني: استبدال Polling بالمزامنة الحدثية (Event-Driven Sync)**
  - *النهج المختار*: استخدام قناة الاتصال المباشر (`onSnapshot`) مع مقارنة ذكية للبيانات قبل تحديث واجهة React.
  - *لماذا*: يمنع إعادة رسم الشاشة (Re-renders) غير الضرورية، ويوفر استهلاك البطارية والبيانات على الموبايل، ويجعل التصفح والفلترة سلسين للغاية.

## 4. البنية التقنية واستراتيجية البيانات

### مخطط البنية وتدفق البيانات

```
┌──────────────────────┐         ┌──────────────────────┐
│    نسخة الكمبيوتر    │         │   نسخة الموبايل PWA  │
│  (واجهة إدارة الجلسات)│         │ (واجهة إدارة الجلسات)│
└──────────┬───────────┘         └──────────┬───────────┘
           │                                │
           │   إضافة / تعديل / حذف مباشر    │
           ▼                                ▼
┌───────────────────────────────────────────────────────┐
│            طبقة المزامنة السحابية الموحدة             │
│   • فحص منع تكرار الجلسات (تطبيع الأسماء العربية)     │
│   • مستمع لحظي صامت (Real-time Snapshot Listener)     │
│   • تحديث الحالة فقط عند تغير البيانات الفعلي          │
└──────────────────────────┬────────────────────────────┘
                           │
                           ▼
┌───────────────────────────────────────────────────────┐
│         قاعدة البيانات السحابية (Firebase Firestore)   │
│  ┌─────────────────────┐   ┌───────────────────────┐  │
│  │  مجموعة الجلسات      │   │    مجموعة العملاء      │  │
│  │     (sessions)      │   │       (clients)       │  │
│  └─────────────────────┘   └───────────────────────┘  │
└───────────────────────────────────────────────────────┘
```

### نموذج البيانات والمجموعات السحابية

1. **مجموعة الجلسات (`sessions`)**:
   - تحتوي كل وثيقة على: المعرف الفريد (`id`)، اسم العميل (`clientName`)، رقم الهاتف (`clientPhone`)، تاريخ الحضور (`attendanceDate`)، وقت الحضور (`attendanceTime`)، التشخيص/الحالة (`condition`)، المبلغ (`amount`)، حالة الدفع (`paymentStatus`)، طريقة الدفع (`paymentMethod`)، الملاحظات (`notes`)، وتاريخ الإنشاء (`createdAt`).
2. **مجموعة العملاء (`clients`)**:
   - تحتوي كل وثيقة على: المعرف الفريد (`id`)، اسم العميل (`name`)، رقم الهاتف (`phone`)، الحالة الأساسية (`primaryCondition`)، تاريخ أول زيارة (`firstVisitDate`)، وتاريخ آخر زيارة (`lastVisitDate`).

### ربط التفاعلات بالحالة السحابية

- **إضافة جلسة جديدة**: التحقق من عدم وجود جلسة مطابقة لنفس العميل (بعد تطبيع الأحرف العربية) في نفس التاريخ والوقت $\leftarrow$ حفظ الوثيقة في مجموعة `sessions` $\leftarrow$ تحديث أو إنشاء ملف العميل تلقائياً في مجموعة `clients`.
- **تعديل جلسة أو تبديل حالة الدفع**: تحديث الوثيقة مباشرة في Firestore $\leftarrow$ انعكاس التعديل لحظياً وبصمت على جميع الأجهزة المتصلة.
- **حذف جلسة أو استعادة البيانات الافتراضية**: حذف الوثيقة مباشرة من Firestore (أو إعادة ضبط المجموعات بالبيانات الأولية عند طلب المستخدم ذلك صراحة) مع تأكيد فوري.
